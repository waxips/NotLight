# Typst + MiTeX formula runtime provenance

NotLight Formula Profile v1 uses a small, replaceable local renderer stack:

- **Typst compiler:** 0.15.1
- **Windows x86-64 artifact:** `typst-x86_64-pc-windows-msvc.zip`
- **Upstream release:** `https://github.com/typst/typst/releases/tag/v0.15.1`
- **Official download landing page:** `https://typst.app/open-source/`
- **License:** Apache-2.0. Typst also ships a `NOTICE` file that must accompany
  redistributed compiler builds.
- **Windows archive SHA-256 pin used by the local checker:**
  `19ce3551153c2fe7ee9fa2f95208310c8f4d3209fedb699e0333faf8913f6736`

MiTeX is installed as a local Typst package:

- **Package:** MiTeX 0.2.7
- **Official Typst Universe page:** `https://typst.app/universe/package/mitex/`
- **Official package archive:** `https://packages.typst.org/preview/mitex-0.2.7.tar.gz`
- **License:** Apache-2.0

The Typst package registry's generated `.tar.gz` byte hash is not used as the
sole long-term package identity because upstream package archives have had
metadata-related hash-instability discussions. `prepare_mitex_windows.ps1`
therefore records the downloaded archive hash for provenance and creates a
stable deterministic digest over the extracted package file paths + SHA-256
values. Release builds re-verify that installed digest before packaging.

## Runtime security / reproducibility contract

NotLight never inserts FormulaObject LaTeX directly into Typst source. The
canonical LaTeX is written to a private per-job `formula.txt`; a fixed NotLight
wrapper reads it as data and passes the string to the local MiTeX package.

Formula compilation pins:

- local package import `@local/mitex:0.2.7`;
- explicit `--package-path` and isolated `--package-cache-path`;
- `--root` set to the private per-job directory;
- `--ignore-system-fonts` so output uses Typst's embedded fonts rather than
  machine-specific fonts;
- `--creation-timestamp 0` and `--jobs 1` for deterministic/bounded work;
- SVG output, rasterized by Godot in a bounded worker.

No `@preview` package import is generated by NotLight's wrapper. Missing Typst
or MiTeX is a supported state: canonical LaTeX remains readable/editable.

## Source-repository policy

The public GitHub source repository does not commit the large `tools/typst/windows/typst.exe` binary. `tools/setup_windows_dependencies.ps1` downloads the pinned official Typst 0.15.1 Windows archive and verifies the SHA-256 above before restoring the compiler locally. The Apache-2.0 license/NOTICE material remains committed.
