# Pinned qpdf Windows backend

NotLight uses qpdf as an **optional local sidecar** for conservative PDF optimization. qpdf is not required to open the project, browse the Resource Library, or render PDFs with the Poppler backend.

## Pinned Windows package

- qpdf release: **12.4.0**
- Upstream: https://github.com/qpdf/qpdf
- Release tag: `v12.4.0`
- Artifact: `qpdf-12.4.0-msvc64.zip`
- Artifact SHA-256: `5bcb25353f7e6df92b5625dbcfe52a5c34a2a5fba2d1a8b98b8a6a0972c3ff72`
- Target: Windows x64, MSVC build
- License: Apache-2.0

Do not silently replace this archive with another qpdf version. Update the pin, checksum, notices and regression corpus together.

## Runtime files retained by NotLight

The dependency audit of the pinned MSVC build shows that NotLight needs only:

```text
tools/qpdf/windows/bin/qpdf.exe
tools/qpdf/windows/bin/qpdf30.dll
```

`qpdf.exe` imports `qpdf30.dll` plus the normal MSVC/UCRT runtime. `qpdf30.dll` likewise uses the MSVC/UCRT runtime and Windows system DLLs.

NotLight intentionally does **not** redistribute copied Microsoft runtime files from the qpdf ZIP (`concrt140.dll`, `msvcp140*.dll`, `vcruntime140*.dll`). Users install the supported Microsoft Visual C++ Redistributable x64 as a Windows prerequisite. Helper programs such as `fix-qdf.exe` and `zlib-flate.exe`, development headers and import/static libraries are not used by NotLight and are excluded from the project/release runtime.

## Refresh procedure

1. Download the official `qpdf-12.4.0-msvc64.zip` artifact.
2. Verify SHA-256 against the value above.
3. Extract `qpdf.exe` and `qpdf30.dll` into `tools/qpdf/windows/bin/`.
4. Keep/update `THIRD_PARTY_LICENSES/QPDF-Apache-2.0.txt` and `THIRD_PARTY_LICENSES/QPDF-NOTICE.md`.
5. Run `tools/check_qpdf_windows.ps1` on a Windows machine with the supported VC++ runtime installed.

The checker can also accept `-ArchivePath` to verify the original downloaded ZIP checksum.

## Runtime policy

- Missing qpdf is a supported application state: PDF rendering continues through Poppler.
- Release packaging expects the pinned qpdf runtime to be present.
- Optimization accepts only argument lists generated by NotLight; documents do not supply arbitrary qpdf flags.
- The original PDF remains canonical. qpdf output is staged, validated, hashed, then committed as a separate durable variant.
