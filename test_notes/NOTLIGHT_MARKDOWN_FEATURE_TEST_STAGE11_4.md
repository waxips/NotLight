## H2 — inline-разметка

Обычный абзац. **Жирный через звёздочки**, __жирный через подчёркивания__, *курсив через звёздочку*, _курсив через подчёркивание_, ~~зачёркнутый текст~~, ==выделенный текст== и `inline_code()`.

Комбинации: **жирный и *курсив внутри***, ~~зачёркнутый с **жирным**~~, ==подсветка с `кодом`==.

Экранирование должно оставлять символы литеральными: \*не курсив\*, \_тоже не курсив\_, \`не inline code\`, \~\~не зачёркнуто\~\~.

## Fenced code — backticks

```cpp
#include <iostream>

int main() {
    std::cout << "NotLight code block" << std::endl;
    return 0;
}
```

У блока должна быть SVG-кнопка копирования. В clipboard должно попасть содержимое блока **без** ``` и без `cpp`.

## Fenced code — tildes

~~~gdscript
func typed_example(value: int) -> String:
    var result: String = "value=%d" % value
    return result
~~~

Этот вариант должен распознаваться тем же fenced-code pipeline.

## Большой абзац для переноса строк

NotLight должен переносить длинный текст внутри доступной ширины без выхода за панель. Этот абзац намеренно длиннее типичной строки: он проверяет перенос, высоту блока, прокрутку Reading view и то, что inline-разметка вроде **важного фрагмента**, *акцента*, ==подсветки== и `small_code()` не ломает геометрию строки при узком окне.

## Контроль границ текущей реализации — ожидается литеральный текст

Следующие конструкции **на Stage 11.4 не заявлены как поддерживаемые**. Они нужны как контроль деградации: Notes не должен повреждать canonical Markdown и не должен притворяться, что умеет их полноценно рендерить.

- rich Notes workspace остаётся полноценным интерактивным вариантом.
