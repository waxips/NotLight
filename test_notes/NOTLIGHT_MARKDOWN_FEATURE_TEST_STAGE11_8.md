# H1 — заголовок первого уровня

Эта заметка предназначена для ручной проверки **всего Markdown-dialect, который заявлен встроенным Notes renderer NotLight Stage 11.8**. Проверь её в режиме «Чтение», в Markdown-редакторе, как лёгкую заметку на доске и — при необходимости — с включённым «Полным рендером обычных заметок» в Custom Performance.

## H2 — базовая inline-разметка

Обычный текст. **Жирный через звёздочки**, __жирный через подчёркивания__, *курсив через звёздочку*, _курсив через подчёркивание_, ~~зачёркнутый текст~~, ==выделенный текст== и `inline_code()`.

Тройные маркеры: ***одновременно жирный и курсивный*** и ___тоже одновременно жирный и курсивный___.

Вложенные комбинации: **жирный и *курсив внутри***, *курсив и **жирный внутри***, ~~зачёркнутый с **жирным** и *курсивом*~~, ==подсветка с `кодом` и **жирным**==.

Экранирование должно оставлять символы литеральными: \*не курсив\*, \_тоже не курсив\_, \`не inline code\`, \~\~не зачёркнуто\~\~, \[\[не wiki-link\]\].

## Fenced code — backticks

```cpp

    std::cout << "NotLight code block" << std::endl;
    return 0;
}
```

У блока должна быть SVG-кнопка копирования. В clipboard должно попасть только содержимое блока — без fences и без `cpp`.

## Fenced code — tildes

~~~gdscript
func typed_example(value: int) -> String:
    var result: String = "value=%d" % value
    return result
~~~

Этот вариант должен распознаваться тем же fenced-code pipeline.

## Block LaTeX — последовательное преобразование в одном блоке

Следующий блок намеренно содержит несколько непустых строк без собственного LaTeX environment. Presentation-layer должен объединить их в `aligned`, **не изменяя canonical Markdown**:

$$
f(x) = x^3 - 2x
f'(x) = 3x^2 - 2
f'(2) = 10
$$

## Block LaTeX — автор сам управляет environment

Если environment уже указан, Notes не должен оборачивать его повторно:

$$
\begin{aligned}
a^2 + b^2 &= c^2 \\
a^2 &= c^2 - b^2 \\
a &= \sqrt{c^2-b^2}
\end{aligned}
$$

Формулы должны выглядеть как часть документа: без плашки «Готово», без ненужного full-width контейнера. Если Formula backend недоступен, должен деградировать только presentation; canonical LaTeX сохраняется.

## Точный переход из «Чтение» в Markdown

Дважды кликни **примерно в середину этого предложения**, например прямо по слову `середину`. NotLight должен перейти в Markdown и поставить caret возле выбранного символа, а не просто в начало всего блока.

Повтори тест на слове **жирный** в этом абзаце и на *курсивном* фрагменте — inline delimiters не должны сдвигать caret на случайную позицию.

## Большой абзац и прокрутка

NotLight должен переносить длинный текст внутри доступной ширины без выхода за панель. Этот абзац намеренно длиннее типичной строки: он проверяет перенос, высоту блока, правый scrollbar Reading view и то, что inline-разметка вроде **важного фрагмента**, *акцента*, ***сильного акцента***, ==подсветки== и `small_code()` не ломает геометрию строки при узком окне. Scrollbar должен использовать визуальный стиль Notes/NotLight, а не системный серый skin.

## Контроль границ текущей реализации — ожидается литеральный текст

Следующие конструкции **на Stage 11.8 не заявлены как полноценно поддерживаемые**. Они нужны как regression-control: Notes не должен повреждать canonical Markdown и не должен изображать поддержку там, где её пока нет.

# Stage 11.8 — визуальная регрессия типографики

Эти строки должны быть **визуально** разными, а не только терять Markdown-маркеры:

Обычный текст рядом с **жирным текстом** рядом с *курсивом* рядом с ***жирным курсивом***.

Через подчёркивания: __жирный__, _курсив_, ___жирный курсив___.

Вложение: **жирный с *курсивом внутри*** и *курсив с **жирным внутри***.

Смешение: **жирный `inline_code` и ==подсветка==**, затем обычный текст.

# Stage 11.8 — компактный LaTeX и выравнивание

Однострочная формула не должна резервировать ширину/высоту raster-tier:

$$
E = mc^2
$$

Последовательное преобразование — canonical Markdown содержит обычные строки, presentation может временно обернуть их в `aligned` и выровнять по первому `=`:

$$
f(x) = x^3 - 2x
f'(x) = 3x^2 - 2
f'(2) = 10
$$

Последовательность с короткими левыми частями:

$$
a = b + c
b = d - e
c = f + g
$$

Автор сам владеет environment — Notes не должен вкладывать второй `aligned`:

$$
\begin{aligned}
a^2 + b^2 &= c^2 \\
a^2 &= c^2 - b^2
\end{aligned}
$$

Высокие глифы/акценты не должны обрезаться после alpha trim:

$$
\int_0^1 \frac{\sqrt{x^2 + 1}}{1 + x^4}\,dx
$$

$$
\sum_{n=1}^{\infty} \frac{1}{n^2} = \frac{\pi^2}{6}
$$

# Stage 11.8 — кириллица и Library embeds

## Кириллическое inline-форматирование

Обычный кириллический текст рядом с **Жирный кириллический текст**, *Курсивный кириллический текст* и ***Жирный курсив кириллицей***.

Также проверь варианты через подчёркивания: __Жирный кириллицей__, _Курсив кириллицей_ и ___Жирный курсив кириллицей через подчёркивания___.

Вложенные комбинации: **Жирный текст, внутри которого *есть кириллический курсив***, а также *Курсивный текст, внутри которого **есть кириллический жирный***.

Экранирование должно оставаться буквальным: \*не курсив кириллицей\*, \**не жирный кириллицей\**.

## Resource Library embed — отсутствующий hash

Следующий блок специально содержит SHA-256, которого почти наверняка нет в локальной Библиотеке. В режиме «Чтение» он должен деградировать в аккуратное состояние «ресурс недоступен», не ломая заметку и граф:

## Resource Library embed — реальный ресурс

1. Импортируй изображение, аудио, видео или PDF в «Библиотеку ресурсов».
2. Открой контекстное меню карточки ресурса.
3. Выбери «Скопировать embed для заметки».
4. Вставь полученную строку **на отдельной строке** вместо примера ниже.
5. Для изображения ожидается inline-preview. Для audio/video/PDF на этом базовом этапе ожидается компактная карточка с переходом в централизованный Library Preview.
6. Экспорт доски с включёнными Notes и «ресурсами, встроенными в заметки» должен захватить этот ресурс, а после импорта embed должен разрешиться по тому же SHA-256 даже при remap локального asset ID.
